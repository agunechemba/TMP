Chapter 1: The Magic of Telling Computers What to Do

Once upon a time, there was a machine that knew nothing at all…

Imagine you have a very large, very fast, very strong robot friend. It can do almost anything — but it knows nothing unless you tell it.

“Please make me a sandwich,” you say.

The robot stands still. It doesn’t know what a sandwich is. It doesn’t know what bread is. It doesn’t even know where the kitchen is.

So you have to say: “Walk to the kitchen. Open the drawer. Pick up the knife. Open the bread box…”

That is what programming is: giving a computer exact, step-by-step instructions so it can do something useful.

The Big Ideas in This Chapter

  • Computers are not smart. They only do what we tell them. They are like a super-fast helper who needs every detail explained.
  • Programming is problem-solving. Big problems are made of little problems. If you can solve the little ones, you can solve the big one.
  • You don’t need to be a genius. You need patience, curiosity, and imagination — three things every kid already has.

A True Story: The Robot That Almost Got It Right

Long ago, a team built a robot cannon called Sergeant York. It was supposed to find enemy airplanes and shoot them down. But during a big demonstration, the robot got confused and pointed its cannons at the audience instead! Everyone ran for their lives.

The lesson? If instructions are even a little bit wrong, a computer can do something very wrong — very fast.

  1. What is something you do every day that a computer could help with?
  2. If you had a robot helper, what would you teach it to do first?
  3. What kind of instructions do you think a robot would need to make a peanut butter sandwich?

Chapter 2: Why Are There So Many Computer Languages?

Why can’t computers just speak English?

A long time ago, computers only understood one language: machine language. It is made of only two numbers: 0 and 1.

A program in machine language looks like this:

0010 1010 0001 1101
0011 1100 1010 1111

Can you read that? No? Neither could most people! So programmers invented assembly language, which uses short words like JMP, MOV, and ADD instead of numbers.

But assembly language was still hard. So people invented high-level languages that look more like human language. One of the first was BASIC, which stands for Beginner’s All-purpose Symbolic Instruction Code.

Why So Many Languages?

Different languages are good at different things:

  • BASIC is simple and friendly. It was made for beginners.
  • C and C++ are powerful. Many big programs like Windows and Photoshop are written in C++.
  • Java can run on almost any computer. It uses something called byte code.
  • JavaScript makes web pages interactive.
  • Python is friendly and popular for science and games.
  • SQL is for talking to databases — giant lists of information.
  • HTML is the language of web pages.
  • Revolution uses English-like sentences, so it is easy to read.

The “Best” Language?

Here is a secret: there is no single best language. It’s like asking, “What is the best tool — a hammer or a screwdriver?” It depends on what you are building.

A great BASIC programmer will always be more productive than a grumpy C++ programmer who has no ideas.

Think About It

  1. What would be a good language for making a web page?
  2. What would be a good language for making a fast video game?
  3. Why do you think programmers invented so many languages?

Chapter 3: How to Plan a Program

Building a program is like baking a cake — you need a recipe first!

Imagine trying to bake a cake by throwing all the ingredients into a bowl at the same time without a recipe. Flour everywhere! Eggs on the floor! A mess!

That’s what happens if you write a program without planning. So before you write any code, you need to think about four things:

The Four Big Questions

  1. What problem does my program solve? If you can’t say it clearly, you can’t build it.
  2. Who is going to use it? A game for kids is different from a tool for doctors.
  3. What kind of computer will it run on? A Windows laptop? A Mac? A phone? A robot?
  4. Who is going to write it? Just you? Or a whole team?

Make a Prototype First

A prototype is a pretend version of your program. It might show the buttons and menus, but clicking them doesn’t do anything yet.

Architects build little models out of cardboard before they build a real skyscraper. Programmers build prototypes before they write real code.

Once you are happy with the prototype, you can start writing the real program.

Pseudocode: Writing Instructions in Plain English

Before you write real code, you can write pseudocode — instructions in plain English that anyone can understand.

For example, here is pseudocode for a program that asks for your name and says hello:

1. Ask the user for their name.
2. Store the name in memory.
3. Print "Hello, [name]!" on the screen.
4. End the program.

Think About It

  1. What problem would you like a program to solve for you?
  2. Who would use your program?
  3. Can you write pseudocode for a program that adds two numbers together?

Chapter 4: The Programmer’s Toolbox

Every wizard needs a wand, a cauldron, and a spellbook.

A programmer needs tools, just like a carpenter needs a hammer and saw. Here are the most important ones:

The Tools

  • Editor: A special text editor where you type your code. It is like a word processor, but it saves plain text files.
  • Compiler: A program that translates your code into machine language (0s and 1s) all at once, creating an executable file.
  • Interpreter: A program that translates your code one line at a time as it runs. It doesn’t create a separate file.
  • Debugger: A tool that helps you find bugs (mistakes) in your program. It can run your code line by line and show you what is happening.
  • Help File Creator: A tool for writing on-screen help so users can figure out how to use your program.
  • Installation Program: A tool that copies your program onto someone else’s computer.

What Is a Bug?

A bug is a mistake in a program. The word comes from a real story: long ago, a moth got stuck inside a computer and stopped it from working. The scientists found it and said, “There’s a bug in the computer!”

Today, bugs are mistakes in code. They can be tiny (a misspelled word) or huge (the program does the wrong thing completely).

A debugger helps you hunt bugs. It can:

  • Step through your program one line at a time.
  • Set breakpoints so the program stops at a certain line.
  • Watch variables to see when their values change.

  1. What is the difference between a compiler and an interpreter?
  2. Why is it impossible to write a program with zero bugs?
  3. If you were a bug hunter, what tool would you use first?

Chapter 5: Getting Started with Code

Let’s make the computer say something!

The best way to learn programming is to start writing programs. In this chapter, we’ll look at the same tiny program in three different languages. The program just prints: It works!

Liberty BASIC

Liberty BASIC is simple and friendly. Here is a whole program:

print "It works!"

That’s it! One line. The word print tells the computer to show something on the screen.

REALbasic

REALbasic is a more advanced version of BASIC. It has a user interface (buttons, windows), so you write code that runs when the user clicks a button:

Sub Action()
  MsgBox "It works!"
End Sub

When the user clicks the button, a message box pops up saying “It works!”

C++

C++ is more complicated. Here is the same program in C++:

#include <iostream>
#include <stdio.h>
int main()
{
  std::cout << "It works!\n";
  std::cout << "\nPress ENTER to continue..." << std::endl;
  getchar();
  return 0;
}

That’s a lot of lines just to say “It works!” C++ is powerful, but it makes easy things hard and hard things easy.

Revolution

Revolution is a scripting language that uses English-like commands. Here is a program that runs when you click a button:

on mouseUp
  put "It works!" into message
end mouseUp

The command put ... into message displays text in a message box.

Which One Should You Learn?

It doesn’t matter which language you start with. The important thing is to start. BASIC is easy and friendly. C++ is powerful. Revolution is simple and readable. Pick one, practice, and have fun!

  1. Which language looked the easiest to you? Why?
  2. What does the word print do in BASIC?
  3. Can you write a program that prints your name instead of “It works!”?

Chapter 6: How a Program Is Built

Every program is made of three simple building blocks.

Every program in the world — from a video game to a web browser — is built from three kinds of instructions: sequencing, branching, and looping.

1. Sequencing

Sequencing means doing one thing after another, in order.

print "First, I wake up."
print "Then, I brush my teeth."
print "Then, I eat breakfast."

The computer runs each line in order, top to bottom.

2. Branching

Branching means making a choice. The computer asks a question and does different things depending on the answer.

IF it is raining THEN
  print "Take an umbrella!"
ELSE
  print "Wear sunglasses!"
END IF

If it is raining, the computer says take an umbrella. If not, it says wear sunglasses.

3. Looping

Looping means repeating something over and over.

FOR I = 1 TO 5
  print "This is loop number "; I
NEXT I

This prints:

This is loop number 1
This is loop number 2
This is loop number 3
This is loop number 4
This is loop number 5

Putting Them Together

Here is a program that asks for a password and keeps asking until you type the right one. It uses sequencing, branching, and looping all together:

password$ = ""
WHILE password$ <> "open"
  PROMPT "Enter your password"; password$
  IF password$ = "open" THEN
    NOTICE "Welcome to the secret club!"
  ELSE
    NOTICE "Try again!"
  END IF
WEND
END

This program keeps asking (looping) until the password is correct, and it uses an IF-THEN statement (branching) to check the answer.

Think About It

  1. What is an example of sequencing in your morning routine?
  2. Can you think of a time you used branching in real life?
  3. What would you do if you had to loop something five times?

Chapter 7: Boxes, Labels, and Notes

How to store information, name it, and leave notes for yourself.

Imagine you have a big pile of boxes. Each box has a label. Some boxes hold numbers. Some boxes hold words. You can put things in a box, take them out, and change what is inside.

In programming, these boxes are called variables.

Variables

A variable is a named place in the computer’s memory where you can store data.

name$ = "Ada"
age = 11
print "Hello, "; name$
print "You are "; age; " years old."

The variable name$ holds a word (string), and the variable age holds a number.

Rules for naming variables:

  • Use descriptive names like firstName or totalPrice.
  • Be consistent with upper- and lowercase letters. Some languages care about the difference between Name and name.
  • In some BASIC dialects, a string variable ends with a dollar sign ($).

Constants

A constant is like a variable, but its value never changes. You give it a name so the number makes sense.

Const INTEREST_RATE = 0.05
balance = 1000
profit = balance * INTEREST_RATE

Instead of typing 0.05 everywhere, you use the name INTEREST_RATE. If the rate changes, you only have to change it in one place.

Comments

Comments are notes for humans. The computer ignores them completely. They help you remember what your code does (and help other people understand it).

' This is a comment in Liberty BASIC
REM This is also a comment
// This is a comment in C++
# This is a comment in Revolution

Good comments explain why you did something, not just what you did.

  1. What is the difference between a variable and a constant?
  2. Why is it helpful to use descriptive variable names?
  3. What kind of comment would you write next to a tricky piece of code?

Chapter 8: Numbers and Words

Computers love to crunch numbers and play with strings.

Computers are great at two things: math and words. In programming, words are called strings because they are like a string of letters, symbols, and spaces.

Math Operators

Here are the symbols you use to do math in code:

  • + addition (2 + 3 = 5)
  • - subtraction (5 - 2 = 3)
  • * multiplication (4 * 7 = 28)
  • / division (10 / 2 = 5)
  • \ integer division (only whole numbers)
  • mod modulo (the remainder after division)
  • ^ exponentiation (2 ^ 3 = 8)

Order of Operations

Just like in math class, some operations happen before others. The computer calculates in this order:

  1. Exponentiation (^)
  2. Multiplication (*) and division (/)
  3. Integer division (\)
  4. Modulo (mod)
  5. Addition (+) and subtraction (-)

If you want to change the order, use parentheses:

result = (3 + 4) ^ 5   ' This adds 3 + 4 first, then raises it to the 5th power
result = 3 + 4 ^ 5      ' This raises 4 to the 5th power first, then adds 3

Strings

A string is anything inside quotation marks:

print "This is a string."
print "So is this: 42"
print "And this: 3.14159"

You can concatenate (join) strings together:

firstName$ = "Ada"
lastName$ = "Lovelace"
fullName$ = firstName$ + " " + lastName$
print fullName$   ' Prints "Ada Lovelace"

Converting Between Numbers and Strings

Sometimes you need to turn a number into a string, or a string into a number. Different languages have different commands for this. For example, in Liberty BASIC:

' Convert a string to a number
age = VAL("42")    ' age is now the number 42

' Convert a number to a string
message$ = STR$(42)  ' message$ is now the string "42"

In Revolution, the language figures it out automatically.

  1. What is the result of 10 / 3? What about 10 \ 3?
  2. What does the mod operator do?
  3. Can you write a program that joins your first name and last name together?

Chapter 9: Making Choices

What if? Or else? The computer can decide.

Computers can’t think, but they can compare. They ask questions like: “Is this number bigger than that one?” “Are these two words the same?” The answer is always true or false.

These true-or-false questions are called Boolean expressions.

Relational Operators

  • < less than
  • > greater than
  • <= less than or equal to
  • >= greater than or equal to
  • = equal to (in some languages, use ==)
  • <> not equal to

IF-THEN Statements

An IF-THEN statement runs some code only if a condition is true:

IF (age >= 18) THEN
  print "You can vote!"
END IF

If age is 18 or more, the program prints the message. Otherwise, it does nothing.

IF-THEN-ELSE Statements

An IF-THEN-ELSE statement gives the computer two choices:

IF (age >= 18) THEN
  print "You can vote!"
ELSE
  print "You are too young to vote."
END IF

Now the program always does something, depending on the age.

SELECT CASE Statements

When you have many possible values, a SELECT CASE statement is cleaner than a long list of IF-THENs:

SELECT CASE grade
  CASE "A"
    print "Excellent!"
  CASE "B"
    print "Good job!"
  CASE "C"
    print "You passed."
  CASE ELSE
    print "Better luck next time."
END SELECT

Boolean Operators

You can combine conditions with AND and OR:

  • AND is true only if both sides are true.
  • OR is true if at least one side is true.
IF (age >= 13) AND (age <= 19) THEN
  print "You are a teenager!"
END IF

Think About It

  1. What is the difference between = and == in some languages?
  2. Can you write an IF-THEN-ELSE statement that checks if a number is positive or negative?
  3. When would you use OR instead of AND?

Chapter 10: Repeating Things Over and Over

Why type the same thing a hundred times when you can loop?

Imagine you have to print the numbers 1 through 1000. You could write 1000 print statements. But that would be silly. Instead, you use a loop.

A loop repeats instructions until a condition is met.

FOR-NEXT Loops

A FOR-NEXT loop repeats a fixed number of times:

FOR I = 1 TO 5
  print "The number is "; I
NEXT I

This prints the numbers 1 through 5. You can count by different numbers, count backwards, or count to a million.

WHILE Loops

A WHILE loop repeats as long as a condition is true:

I = 0
WHILE (I < 5)
  print "I is "; I
  I = I + 1
WEND

This does the same thing as the FOR-NEXT loop, but you control the condition yourself.

Endless Loops

If a loop never stops, the program freezes. This is called an endless loop. The most common causes are:

  • Forgetting to change the variable inside the loop.
  • Setting the variable inside the loop so it never reaches the exit condition.

Always make sure your loop will eventually stop!

Think About It

  1. What is the difference between a FOR-NEXT loop and a WHILE loop?
  2. Why is an endless loop bad?
  3. Can you write a loop that counts from 10 down to 1?

Chapter 11: Little Programs Inside Big Programs

Divide and conquer!

A big program can be hard to read. Imagine a book with no chapters, no paragraphs, no spaces — just one giant wall of text. That would be terrible!

Programmers break big programs into smaller pieces called subprograms (also called methods, functions, procedures, or handlers). Each subprogram does one job.

Why Use Subprograms?

  • They make big programs easier to read.
  • They let you reuse code instead of writing the same thing over and over.
  • They make it easier to fix bugs because you know exactly where to look.

Creating Subprograms in Liberty BASIC

GOSUB [sayHello]
END

[sayHello]
  print "Hello!"
  RETURN

The GOSUB command jumps to the subprogram, and RETURN goes back to where it left off.

Functions: Subprograms That Return a Value

A function is a special kind of subprogram that calculates something and gives you the answer.

print cube(3)

FUNCTION cube(x)
  cube = x * x * x
END FUNCTION

This prints 27 because 3 × 3 × 3 = 27.

Passing Parameters

You can send data into a subprogram. The data is called a parameter.

CALL greet "Ada"

SUB greet name$
  print "Hello, "; name$; "!"
END SUB

This prints “Hello, Ada!” The subprogram accepted the name and used it.

Think About It

  1. What is a subprogram?
  2. Why would you want to use a function instead of just writing the calculation every time?
  3. Can you think of a task in your life that could be broken into smaller steps?

Chapter 12: Rows of Boxes

When one box isn’t enough.

Imagine you need to store the names of 30 students. You could make 30 separate variables: name1, name2, name3… but that would be exhausting.

Instead, you use an array — a row of boxes all with the same name, but each with a number.

Creating an Array

In Liberty BASIC:

DIM names$(5)

This creates an array called names$ with 6 slots (numbered 0 through 5). Why 6? Because arrays start counting at 0!

In C++:

string names[5];

Storing and Retrieving Data

names$(0) = "Ada"
names$(1) = "Grace"
names$(2) = "Alan"
print names$(0)   ' Prints "Ada"

You use the array name plus a number in parentheses (or brackets in C++) to say which slot you want.

Loops and Arrays

Loops and arrays are best friends. You can use a FOR-NEXT loop to fill an array or read from it:

FOR I = 0 TO 2
  print names$(I)
NEXT I

Dynamic Arrays

A dynamic array can grow or shrink while the program runs. In REALbasic, you can use commands like Append, Insert, and Remove. In C++, you use a pointer and the new keyword.

Two-Dimensional Arrays

A two-dimensional array is like a grid or a table. You can store rows and columns of data.

DIM grid(2, 1)
grid(0, 0) = "A"
grid(0, 1) = "B"
grid(1, 0) = "C"
grid(1, 1) = "D"

Think About It

  1. Why do arrays start at 0 in many languages?
  2. What is the advantage of an array over many separate variables?
  3. What kind of data could you store in a two-dimensional array?

Chapter 13: Building with Objects

Big programs are easier to build when you use Lego bricks.

Imagine you are building a giant castle out of Lego bricks. Each brick is a separate piece, but together they make something amazing. Object-oriented programming (OOP) is like that — you build programs out of separate pieces called objects.

Encapsulation: Keeping Things Private

An object bundles together data and the instructions that work on that data. It keeps them safe from other parts of the program.

Think of a TV remote. You can press buttons (the instructions), but you don’t need to know how the inside works. The remote is an object.

Classes: Blueprints for Objects

A class is a blueprint. An object is a thing built from that blueprint.

For example, a Monster class defines what a monster has (x and y coordinates) and what it can do (move, initialize). You can create many monsters from that one class.

class Monster {
public:
  int x;
  int y;
  void move(int dx, int dy);
};

Inheritance: Reusing Code

Inheritance lets you create a new class based on an old one. The new class gets all the old class’s features and can add its own.

For example, a Person class can inherit from Monster and add an ammo property and a shoot method.

Polymorphism: Same Name, Different Action

Polymorphism lets two different objects use the same method name but do different things. It’s like how a dog and a cat both have a speak() method, but one says “Woof!” and the other says “Meow!”

Part Three: Advanced Magic

Chapter 14: Sorting and Searching

How do computers find things and put them in order?

Imagine a library with 10,000 books, all piled randomly on the floor. If you wanted to find a specific book, it would take forever. But if the books were sorted alphabetically on shelves, you could find one in seconds.

Computers face the same problem. They need to sort data and search through it efficiently.

Sorting Algorithms

There are many ways to sort data:

  • Insertion Sort: Like sorting playing cards in your hand. Pick up one card at a time and put it in the right place.
  • Bubble Sort: Compare pairs of items and swap them if they are out of order. Repeat until everything is sorted.
  • Shell Sort: Divide the list into smaller lists, sort those, then combine them.
  • Quicksort: Pick a number, put smaller numbers on one side and larger numbers on the other, then repeat.

Searching Algorithms

  • Sequential Search: Look at every item one by one until you find what you want. Simple but slow for big lists.
  • Binary Search: Cut the list in half, check the middle, and keep cutting until you find it. Much faster, but the list must be sorted first.

Big-O Notation

Computer scientists use something called Big-O notation to describe how fast an algorithm is. It looks at how the time grows as the list gets bigger.

For example, a sequential search is O(n) — if the list doubles, the search takes twice as long. A binary search is O(log n) — much faster for big lists.

  1. Which sorting algorithm is easiest to understand?

Chapter 15: Finding and Fixing Bugs

Every program has bugs. The trick is finding them.

No program is perfect. Even programs written by experts have bugs. The key is to find and fix them before they cause too much trouble.

Three Kinds of Bugs

  • Syntax errors: You typed a command wrong. The computer can’t understand it. Example: typing prnt instead of print.
  • Run-time errors: Something unexpected happens while the program is running. Example: asking the user for a number and they type a word.
  • Logic errors: The program runs, but it does the wrong thing. Example: a program that adds when it should subtract.

Debugging Tools

  • Stepping: Run the program one line at a time to see exactly what happens.
  • Breakpoints: Tell the program to stop at a certain line so you can examine it.
  • Watching: Keep an eye on a variable to see when it changes.

Famous Bugs

In 1962, a NASA rocket called Mariner 1 had to be destroyed because of a single typo in the code. A comma was typed as a period, which changed a loop into a wrong assignment. Millions of dollars lost!

The lesson: small bugs can cause big problems.

Chapter 16: Making Programs Faster and Better

Optimization: the art of tuning up your code.

A program that works is great. A program that works and runs fast is even better. Making a program faster is called optimization.

Choose the Right Data Structure

If you need to store a list of items that can grow, use a dynamic array instead of a fixed-size array that might be too small or too large.

Choose the Right Algorithm

Sorting 30,000 names with bubble sort is slow. Quicksort is much faster. Picking the right algorithm makes a huge difference.

Fine-Tune Your Code

  • Put conditions most likely to be false first in an AND expression.
  • Don’t run a FOR-NEXT loop needlessly.
  • Don’t put unnecessary instructions inside a loop.
  • Use the correct data types to save memory.
  • Use built-in commands when possible.

Use a Faster Language or Compiler

Machine code is fastest. Assembly language is next. C and C++ are faster than BASIC or Pascal. Different compilers can also produce faster or slower programs from the same code.

  2. What is one way to make a loop faster?

Chapter 17: Making Programs Easy to Use

The user interface is the face of your program.

Imagine a beautiful restaurant with delicious food but a dirty front door and a confusing menu. You might not go in at all.

The same is true for programs. A great program with a bad user interface will be ignored.

Command-Line Interfaces

The simplest interface is a command line, where the user types text commands. It’s powerful, but it’s not very friendly.

Graphical User Interfaces (GUIs)

Most modern programs use GUIs with windows, buttons, menus, and icons. They are much easier for most people to use.

Common controls include:

  • Command buttons: Click to do something.
  • Check boxes: Choose one or more options.
  • Radio buttons: Choose exactly one option.
  • List boxes and combo boxes: Pick from a list of choices.
  • Text boxes: Type something.
  • Labels: Display text that the user cannot change.

Events

When a user clicks a button or types in a text box, that’s called an event. Your program listens for events and responds to them.

In REALbasic and Revolution, you can create event handlers by double-clicking a control and writing code.

  1. What is the difference between a check box and a radio button?
  2. Why is a GUI usually better than a command line for beginners?
  3. What makes a user interface easy to use?

Part Four: The Internet

Chapter 18: Building Web Pages with HTML

The language of the web.

Every web page you have ever visited is built with a language called HTML — HyperText Markup Language. It’s not really a programming language. It’s a way of describing how content should look.

Tags

HTML uses tags written in angle brackets. Most tags come in pairs: an opening tag and a closing tag.

<h1>This is a heading</h1>
<p>This is a paragraph.</p>
<b>This is bold text.</b>
<i>This is italic text.</i>

The Structure of a Web Page

<!DOCTYPE html>
<html>
  <head>
    <title>My Awesome Page</title>
  </head>
  <body>
    <h1>Welcome!</h1>
    <p>This is my first web page.</p>
  </body>
</html>

The <title> appears in the browser tab. Everything inside <body> appears on the page.

Lists and Links

<ul>
  <li>First item</li>
  <li>Second item</li>
</ul>

<a href="https://www.example.com">Click here!</a>

<ul> makes a bulleted list. <a> makes a link.

Images

<img src="my-picture.jpg" alt="A picture of my cat">

The src attribute tells the browser where to find the image.

Forms

Forms let users type information and submit it. They can include text boxes, buttons, check boxes, and radio buttons.

<form>
  <label>Your name: <input type="text" name="name"></label>
  <input type="submit" value="Send">
</form>

  1. What is the difference between <b> and <i>?
  2. What does the <title> tag do?

Part Four: The Internet

Chapter 19: Making Web Pages Come Alive with JavaScript

Add interactivity to your web pages.

HTML makes pretty web pages, but they just sit there. JavaScript makes them interactive — you can click buttons, play games, and respond to the user.

Adding JavaScript to a Page

<script>
  alert("Hello, world!");
</script>

This pops up an alert box when the page loads.

Variables in JavaScript

var name = "Ada";
var age = 11;
document.write("Hello, " + name + "!");

JavaScript uses var to create variables. The document.write command prints text to the page.

Dialog Boxes

alert("This is an alert!");
var answer = confirm("Do you want to continue?");
var name = prompt("What is your name?", "Type here");

JavaScript has three kinds of dialog boxes: alert, confirm, and prompt.

Functions

function square(x) {
  return x * x;
}
document.write(square(5));  // Prints 25

Functions let you reuse code and keep your program organized.

Opening and Closing Windows

var myWindow = window.open("page.html", "myWindow", "width=400,height=300");
myWindow.close();

You can open new browser windows and control their appearance.

Chapter 20: Java Applets — Mini Programs for the Web

Small but powerful programs that run in your browser.

Java is a powerful programming language that can create two kinds of programs: full applications and applets — tiny programs that run inside a web browser.

How Java Applets Work

Java code is compiled into byte code (files ending in .class). The byte code runs on a Java Virtual Machine (JVM), which translates it into machine language for whatever computer you are using.

This means the same Java applet can run on Windows, Mac, or Linux — as long as the computer has a JVM.

Adding an Applet to a Web Page

<applet code="MyApplet.class" width="300" height="200">
  Your browser does not support Java.
</applet>

The width and height attributes define the size of the applet window.

Aligning and Spacing

You can use align to position text around the applet, and hspace and vspace to add space between the applet and the text.

<applet code="MyApplet.class" width="250" height="150" align="middle" hspace="20" vspace="10">
</applet>

Appendix

Glossary of Useful Terms

A quick reference for young coders.

Algorithm
A step-by-step way to solve a problem.
Array
A row of boxes that all hold the same kind of data, each with a number.
Bug
A mistake in a program.
Byte code
An in-between language that Java programs are compiled into.
Class
A blueprint for making objects.
Compiler
A program that translates code into machine language all at once.
Constant
A named value that never changes.
Debugger
A tool for finding and fixing bugs.
Function
A subprogram that calculates and returns a value.
Integer
A whole number (no decimals).
Interpreter
A program that translates and runs code one line at a time.
Loop
Instructions that repeat.
Machine language
The 0s and 1s that computers understand directly.
Object
A bundle of data and instructions built from a class.
Parameter
Data that you pass into a subprogram.
Pseudocode
Plain-English instructions that describe what a program should do.
String
Text inside quotation marks.
Subprogram
A small program inside a bigger program.
Variable
A named box that holds data.
